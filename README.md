# B站首页增强（Edge / Chrome 扩展）

为 bilibili.com 网页版首页打造的三个增强功能：

1. **换一换找回** — 点太快错过了想看的视频？
   - "换一换"正下方新增两个**同风格按钮**：`上一批`（逐批往回翻）、`历史`（历史面板）
   - **批次 = 每次点击"换一换"时主页顶部的前 6 个视频**（弹窗可调 4–12）。实测"换一换"只替换顶部区域，向下滚动加载的内容不会混入历史，批次之间不会互相重复
   - 历史面板与主页推荐流同款卡片风格：**封面 + 标题 + UP主 + 播放量/时长**，支持按标题/UP主搜索，"查看此批"直接回放
   - 默认保留最近 50 批，可在扩展弹窗调整，重启浏览器也不丢
2. **推荐位广告过滤（原位替换）** — 识别推荐流里的广告卡（`cm.bilibili.com` 链接、"广告"角标、接口 `goto=ad`、楼层广告位四重信号），**原位替换**为热门视频：槽位外壳不动、只换内容，网格零回流，彻底避免"隐藏广告后底部错位"；直播卡与"继续观看"卡保留不动；"登录提示"等非视频卡一并替换

### 原位替换解决错位问题

传统广告过滤方式（隐藏元素）会导致网格回流错位，因为：
- 隐藏广告后，后续元素会自动上移填补空位
- 用户滚动时页面布局发生变化
- 视觉体验差，甚至可能误触广告

本扩展采用**原位替换方案**：
1. **保留槽位外壳**：广告卡的外层容器节点保持不动
2. **隐藏原生内容**：用 CSS 隐藏广告卡的原生内容
3. **插入补位视频**：扩展渲染的补位视频作为子节点插入同一槽位
4. **网格几何不变**：所有子项的坐标保持不变，零回流

实测效果：24个子项的坐标变化为 0，彻底解决底部行错位问题。
3. **破茧** —
   - **注入**：每批（顶部 `batchSize` 个视频槽）按比例（默认 30%）把**末尾几张原位替换**为热门榜/排行榜等非个性化内容——注入内容直接出现在第一屏视线里，带来源角标

### 破茧视频可见性问题解决方案

传统破茧注入方式（追加到网格末尾）导致：
- 破茧视频出现在页面底部，用户需要滚动才能看到
- 热门内容被淹没在个性化推荐中

本扩展采用**顶批末尾原位替换方案**：
1. **定位顶部批次**：在"换一换"点击瞬间，捕获顶部前 N 个视频槽
2. **末尾替换**：将批次末尾的几张视频槽原位替换为破茧内容
3. **第一屏展示**：热门内容直接出现在用户视线范围内
4. **来源标识**：破茧视频带来源角标，用户可识别内容来源

实测效果：2张热门卡出现在第一屏，解决破茧视频不可见问题。
   - **统计**：首页"统计"按钮查看最近 30 批的**主频道分布**（游戏/知识/音乐…，通过视频详情接口的 tid_v2 + B站视频页内嵌频道表解析，按 bvid 本地缓存）、茧房指数（最集中频道占比）、覆盖频道数、已关注内容占比

## 分区统计（主频道维度）详解

B站已全面隐去视频的 tname（分区名称），仅保留 tid/tid_v2。本扩展通过以下方式实现分区统计：

1. **频道表收割**：从任意视频页 HTML 内嵌的 `channelKv` 数据中提取 tid→名称映射（实测 236 条分区，含主频道和子频道）
2. **视频详情接口**：调用 `https://api.bilibili.com/x/web-interface/view?bvid=` 获取视频的 tid_v2
3. **本地缓存**：按 bvid 缓存分区信息，避免重复请求
4. **异步补齐**：批次统计时异步补齐缺失的分区信息，保证统计完整性
5. **统计指标**：
   - 主频道分布：各分区视频占比（游戏/知识/音乐/生活等）
   - 茧房指数：最集中频道的占比（反映推荐内容的多样性）
   - 覆盖频道数：统计批次中出现的不同频道数量
   - 已关注内容占比：已关注UP主视频的比例

所有分区数据仅本地存储，不上传任何服务器。

所有数据只保存在浏览器本地（`chrome.storage.local`），不上传任何服务器。

## 安装（Edge）

1. 打开 Edge，地址栏输入 `edge://extensions`
2. 打开右上角/左侧的 **开发人员模式**
3. 点击 **加载解压缩的扩展**，选择本文件夹（`bilibili-home-enhancer`）
4. 打开 [bilibili.com 首页](https://www.bilibili.com/)，推荐流右侧"换一换"下方会出现粉色按钮栈

Chrome 安装方式相同（`chrome://extensions`）。需要 Chrome/Edge 111+（MV3 的 MAIN world 内容脚本）。

## 使用

| 入口 | 作用 |
| --- | --- |
| 首页"换一换"下方 `上一批` 按钮 | 逐批回退查看历史推荐，再点继续往回翻 |
| 首页"换一换"下方 `历史` 按钮 | 历史网格面板：搜索、按批次浏览、一键回放任意一批 |
| 回放面板顶部 `‹ ›` / `回到最新` | 回放中逐批前进 / 返回实时推荐（`Esc` 关闭） |
| 历史面板右上角 `茧房统计` | 主频道分布、茧房指数、已关注占比、本批处理概况 |
| 工具栏扩展图标 | 功能开关：广告过滤/补位、历史深度、每批数量、破茧比例（0–50%）等 |

## 工作原理（简）

- **捕获层双通道**：首页首批推荐是服务端渲染的（没有客户端请求），因此以 **DOM 抓取**为主通道；同时通过 MAIN world 注入脚本包装页面的 `fetch`/`XMLHttpRequest`，截获推荐接口响应（`data.item[]`）按 bvid 增强字段（UP主 mid、是否已关注、播放量等）。
- **批次快照**：仅两个时机快照"顶部前 N 个视频槽"（默认 6，可调）：首屏加载完成、点击"换一换"的瞬间（捕获阶段，抢在 B 站替换 DOM 之前）。无限滚动加载只喂"近期已见"去重集合，不产生新批次。
- **原位替换**：广告槽/破茧槽的**外壳节点不动**（网格几何零变化，不触发回流错位），原生内容用 CSS 隐藏，扩展渲染的卡片作为子节点插入同一槽位；点击"换一换"瞬间先撤销替换再让 B 站重建 DOM。
- **自触发防护**：管线前后对比批次签名，签名未变则跳过，防止自己改 DOM 触发 MutationObserver 死循环。

## 故障排查

- **升级扩展后"改了没生效"**：必须在 `edge://extensions` 点扩展卡片上的 **重新加载**（↻），再刷新 B 站页面。确认方法：扩展弹窗右下角显示当前版本号；或 B 站页面按 F12，Console 第一条应有 `[B站首页增强] vX.X.X 已加载`。
- **功能不生效**：确认在 `www.bilibili.com` 首页（推荐流页面）；按 F12 看 Console 是否有报错。
- **清空历史**：弹窗点"清空推荐历史与统计"后，所有打开的 B 站标签页会实时同步清空（内存 + 存储双层一致）。
- **按钮栈/广告过滤失效（B站改版）**：选择器集中在 `content/config.js`，顶部注释标明实测日期；用 F12 检查元素更新对应选择器即可，其余逻辑不依赖具体类名（网格容器是自动探测的）。
- **破茧内容拉取失败**：会自动降级走后台代理；仍失败则注入/补位暂停（不影响其他功能）。
- **图标需重新生成**：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/gen-icons.ps1`。

## 已知限制

- 注入/替换/回放卡片不带 B 站原生的"不感兴趣/稍后再看"浮层，点击即打开视频页。
- 频道统计依赖视频详情接口（每批最多十几个轻量请求，按 bvid 本地缓存永不重复）；频道名称表首次使用时从任意视频页 HTML 收割一次并永久缓存，接口失败的视频按"未识别"处理，不计入分布。
- 历史批次里较早的封面图 URL 可能被 CDN 过期，显示为灰底（链接仍有效）。
- "换一换"的点击行为属于 B 站自身逻辑，本扩展不模拟、不干预其推荐请求。
